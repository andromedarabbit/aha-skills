# 목표

경력회고(career-memoir) 스킬처럼 **AI가 저자(사용자)를 인터뷰해 재료를 수집하고, 그 근거 위에 산문 블로그 글을 쓰는** 에이전트 스킬을 만든다. 오픈소스 구현체를 조사·평가해서 자체구현 여부를 정하는 것부터 시작한다(조사 결과는 `2026-08-26-writing-experts-blog-interview-research.md`).

# 배경: 이미 완료된 선행 작업

1. **경력회고 스킬**: `skills/writing-experts/career-memoir-{interviewer,compiler}` — 인터뷰 → 압축(distiller) → 컴파일(worker) → 감사(auditor) 파이프라인 확립
2. **설계 패턴 문서화**: `docs/solutions/skill-design/career-memoir-interview-pipeline.md` — 인터뷰형 글쓰기 스킬의 일반화된 6패턴 (두 계층 상태, 질문 은행, Stage 게이트, 시험 초안 병렬 비교, 감사, 윤문 불변 전제)
3. **vault blog policy**: `Workflows/policy/writing-policy.blog.md` — 토픽→초안 파이프라인은 있으나 인터뷰로 재료를 수집하는 단계가 없음

# 요구사항

## 스킬이 가져야 할 성격 (사용자 방향)

- 저자를 **인터뷰하면서** 글의 재료(경험·주장·사례·디테일)를 수집한다 — 인터뷰는 **재료 수집 과정**이고 출력은 일반 산문 블로그 글 (Q&A 글 형식이 아님)
- 인터뷰로 모은 발언 위에서만 글을 쓴다 — "추출 not 생성" (career-memoir 원칙 유지)
- 근거 없는 서술은 auditor가 걸어내고, 삭제하거나 기록 내 근거로 대체한다
- **aha-skills는 notes vault와 독립적이어야 한다** — vault 경로·특정 저장소 경로를 스킬에 굽지 않는다. 작업 루트는 호출 시점(인자/현재 디렉토리)에 결정한다
- 1~3세션 규모의 블로그 글에 맞춘 가벼운 세션 구조 (경력회고의 수 주 규모 대비)

## 오픈소스 조사 질문

"인터뷰 기반 블로그 글쓰기"를 하는 적당한 오픈소스 구현체가 있는가? 있다면 자체구현 대비 우위가 있는가?

# 결정 사항 (2026-08-26 사용자 확인)

1. **자체구현 확정** — 오픈소스 후보가 사실상 없어 (유일한 인터뷰 기반 후보가 0★ 영어 개인 프로젝트) 경력회고 골격을 복제·적응한다. blog-skills의 인터뷰 기법은 아이디어로만 차용
2. **인터뷰 = 재료 수집 과정**, 출력은 일반 산문
3. **vault 독립** — 경력회고가 vault 이동 후 스테일 경로가 된 전례를 반면교사

# 스코프 밖

- 이미지 생성, SEO 최적화, 발행 자동화
- vault write-* 파이프라인 직접 연계 (독립성 결정으로 제외 — 완성 초안을 어디로 옮길지는 런타임에 사용자가 선택)
- Q&A 인터뷰 형식 출력
- humanize-korean 자동 호출 (컴파일 완료 후 인계 안내만)
