# 한국어 콘텐츠 가이드라인

이 문서는 한국어 Agent Skills를 작성할 때 따라야 할 언어 및 스타일 가이드라인입니다.

## 언어 사용

### 스킬 파일

| 파일 | 언어 | 설명 |
|------|------|------|
| SKILL.md | 한국어 | 스킬 정의 본문 |
| README.md | 한국어 | 사용자용 문서 |
| GUIDELINES.md | 한국어 | 구현 가이드라인 |
| REFERENCE.md | 한국어 | 레퍼런스 문서 |
| TROUBLESHOOTING.md | 한국어 | 문제 해결 가이드 |

### 루트 문서

| 파일 | 언어 | 설명 |
|------|------|------|
| README.md | 한국어 | 저장소 개요 |
| CONTRIBUTING.md | 한국어 | 기여 가이드라인 |
| CHANGELOG.md | 한국어 | 버전 기록 |

### 코드

| 요소 | 언어 | 예시 |
|------|------|------|
| 변수명 | 영어 | `pipeline_id`, `job_name` |
| 함수명 | 영어 | `check_dependencies()`, `analyze_logs()` |
| 주석 | 한국어·영어 모두 허용 (강제하지 않음) | `# Check if glab is installed` |
| 사용자 메시지 | 한국어 | `echo "# glab가 설치되어 있지 않습니다"` |

## 한글 맞춤법

### 띄어쓰기

한글 맞춤법 규정에 따라 띄어쓰기를 합니다:

```markdown
# 올바름
GitLab CI 파이프라인을 분석합니다
배민 데이터플랫폼 팀의 스킬입니다

# 잘못됨
GitLab CI파이프라인을분석합니다
배민데이터플랫폼팀의스킬입니다
```

### 외래어 표기

외래어는 국립국어원의 외래어 표기법을 따릅니다:

| 단어 | 올바름 | 비고 |
|------|--------|------|
| Agent | 에이전트 | |
| Pipeline | 파이프라인 | |
| Job | 잡 | 또는 '작업' |
| Hook | 훅 | |
| Fork | 포크 | |
| Skill | 스킬 | |

### 전문용어

기술 용어는 원어를 사용하되 필요시 설명을 덧붙입니다:

```markdown
# 일반적인 용어는 원어 사용
GitLab CI/CD 파이프라인
Merge Request (MR)
Pull Request (PR)

# 설명이 필요한 경우
잡(Job) - CI 파이프라인의 개별 작업 단위
훅(Hook) - 특정 이벤트 발생 시 실행되는 스크립트
```


## 머리말과 꼬리말

### 호칭

사용자를 부를 때는 존중하지만 지나치게 높이지 않습니다:

```markdown
# 올바음
다음 단계를 따라주세요
사용자가 입력한 정보를 확인합니다

# 피하세요
고객님께서는 다음 단계를 따라주시기 바랍니다
고객님께서 입력하신 정보를 확인합니다
```

### 종결어미

```markdown
# 명확한 안내
~합니다, ~입니다, ~세요

# 질문
~겠습니까?, ~인가요?

# 제안
~하는 것을 권장합니다, ~것입니다
```

## 문서 구조

## 명확성

### 간결한 표현

```markdown
# 좋음
glab CLI를 사용해 파이프라인 실패 원인을 분석합니다

# 피하세요 (너무 긺)
glab라는 명령행 인터페이스 도구를 활용하여 GitLab CI/CD 파이프라인에서 발생한
다양한 종류의 실패 상황의 근본적인 원인을 분석하고 진단하는 기능을 제공합니다
```

### 능동태

```markdown
# 좋음 (능동태)
이 스킬은 파이프라인을 분석합니다
분석 결과를 표시합니다

# 피하세요 (수동태)
파이프라인이 이 스킬에 의해 분석됩니다
분석 결과가 표시됩니다
```

## 코드와 메시지

### 사용자 메시지

스크립트에서 사용자에게 표시하는 메시지는 한국어로 작성합니다:

```bash
#!/bin/bash
# 사용자 메시지는 한국어
echo "# GitLab CI 파이프라인을 분석합니다..."

# 변수명과 함수명은 영어
local pipeline_id="$1"

analyze_pipeline() {
    ...
}
```

### 에러 메시지

명확하고 조치 가능한 에러 메시지를 작성합니다:

```bash
#!/bin/bash
# 좋음 (명확하고 조치 가능)
echo "# ⚠️ 오류: glab가 설치되지 않았습니다"
echo "# 설치 방법: brew install glab"

# 피하세요 (모호함)
echo "# 오류 발생"
echo "# 다시 시도하세요"
```

## 번역

### 기술 용어 번역

| 원어 | 번역 | 사용 |
|------|------|------|
| Pipeline | 파이프라인 | ✅ 사용 |
| Hook | 훅 | ✅ 사용 |
| Job | 잡 / 작업 | ⚠️ 상황에 따라 |
| Fork | 포크 | ✅ 사용 |
| Deploy | 배포 | ✅ 사용 |
| Lint | 린트 | ✅ 사용 |
| Log | 로그 | ✅ 사용 |
| Merge Request | 병합 요청 | ⚠️ MR도 사용 |
| Pull Request | 풀 리퀘스트 | ⚠️ PR도 사용 |

### 번역하지 않는 용어

다음 용어는 원어를 유지합니다:

- 제품명: GitLab, GitHub, Kubernetes, Docker
- 명령어: git, kubectl, bash, jq
- 파일 확장자: .md, .sh, .yaml
- 기술 약어: CI, CD, API, CLI, URL
