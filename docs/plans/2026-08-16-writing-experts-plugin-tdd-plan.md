# TDD Plan — career-memoir 스킬 패키지 개선

`claude-plan.md`(rev 2)의 구조를 미러링하는 검증 계획. 이 프로젝트는 런타임 코드가 없는 프롬프트·파일 패키지다 — "테스트"는 **각 단계 구현 전에 먼저 정의하고, 구현 후 통과를 확인하는 검증 스텁**이다. 테스트 프레임워크는 없고, 검증 수단은 파일 내용 점검(grep·카운트)과 dry-run 실행이다. 확립된 검증 철학: 시험 인터뷰(이미 세션 1에서 사용), "검증 수단을 하나 더 확보"(vault 교훈).

각 단계의 검증 스텁은 **구현 시작 전에 이 문서에서 해당 단계 분절을 먼저 읽고** 구현 후 순서대로 통과 확인한다.

## 1단계 — references/state-schema.md

구현 전 정의할 검증:

- 검증: 스키마 문서가 세션 원문 계층 섹션(형식·파일명 규칙·추기 빈도·불변식)을 모두 기술하는가 — "답변을 받을 때마다" 문구 존재 여부 grep
- 검증: "source of truth" 문구 존재 — 원문 계층의 지위가 명시됐는가
- 검증: 압축 상태 섹션 목록에 holding 큐(유형·상태·회수 조건 포함)와 "제안"이 포함됐는가
- 검증: Stage 2 완료 신호 정의(`stage: 2` + 비빈 장면표)가 게이트가 판정 가능한 형태로 쓰였는가
- 검증: 매핑 표(기존 7섹션 → 신규 스키마) 존재 — 표의 행 수가 기존 섹션 수 이상인가
- 검증: pre-commit 대응(sessions/ exclude) 절차가 스키마에 명시됐는가
- 검증: 마이그레이션 절차가 인용 16개·Spine·패턴 노트를 각각 어디로 보내는지 지정하는가

## 2단계 — references/question-bank.md

- 검증: 모든 차용 질문에 출처 URL 또는 저장소 표기가 붙는가 — URL 미포함 질문 항목 카운트 0
- 검증: 라이선스 미홀장 4곳(memorist-agent, AutoSkill, writing-dna-discovery, bookstrap) 이름이 "직접 복사 금지" 규칙 문맥 외에 질문 원문 출처로 등장하지 않는가
- 검증: 씨앗 질문 3개(아웃사이더·소수정예·사람 성장)의 변주가 존재하는가 — 키워드 grep으로 3개 모두 hit
- 검증: StoryCorps 파생 세트가 15개 내외이며 원문 병기됐는가
- 검증: 8질문 대응 관계(특히 4번·7번 옆 반사실·대가 배치)가 명시됐는가

## 3단계 — references/probe-taxonomy.md

- 검증: 탐침 3유형 + 감정 탐구형이 각각 정의·한국어 예시 1개 이상을 갖는가
- 검증: 표준 후속 3인자("그다음에 무슨 일이"·"어떤 기분이었나"·"무슨 생각을 했나") 존재 grep
- 검증: 인용 앵커링 예시가 실제 인용 발언(예: "싸움에서 벗어날 생각만 했다")을 인용하는 형태인가
- 검증: push back 규칙과 페이싱 안전 규칙(후퇴 신호→미응답 기록)이 구분되어 존재하는가
- 검증: 탐침 유형 선언 방식(질문 앞 표기 등)이 정의됐는가

## 4단계 — interviewer SKILL.md + distiller

- 검증: description(frontmatter)에 부정 범위("산문 작성·정리는 compiler 담당") 문구 존재 grep
- 검증: 세션 시작 루틴에 holding 큐 회수 확인·제안 승인 항목 존재
- 검증: 세션 3단 구조(워밍업/본론/클로징 성찰)·세션 종료 반사 단계 존재
- 검증: 원문 축적 지시가 "답변마다(늦어도 2~3답변 주기)"를 따르는가 — 스키마와 문구 불일치 여부
- 검증: 질문 자기점검 체크리스트가 6~8줄 이내로 본문에 있고 4평가축+거부 가능성+탐침 유형을 포함하는가
- 검증: 완료 판정("동료에게 설명 가능")·정리 게이트 문구 존재
- 검증: distiller 에이전트 frontmatter(name/description/tools=Read/Write/Edit) 유효, "사용자와 대화 불가→제안 섹션" 규칙 포함
- 검증: SKILL.md 본문 150줄 상한 준수 — `wc -l` 확인

## 5단계 — compiler 스킬 + worker

- 검증: description에 부정 범위("인터뷰 진행은 interviewer 담당") 존재 grep
- 검증: 전제 게이트가 Stage 2 완료 신호 정의를 참조하는가 — 스키마와 동일 판정식인지 대조
- 검증: 프로토콜에 교정 후 재감사·상한 2회·초과 시 사용자 보고가 명시됐는가
- 검증: draft 버전 규칙("N은 감사 통과 확정 시 증가") 문구 존재
- 검증: 목소리 컴파일 시점 도출 + spec 편차 명시 문구 존재
- 검증: im-not-ai 인계 안내(ce-doc-review → humanize-korean 순서) 존재
- 검증: worker 에이전트 tools=Read/Write, 근거 각조·조립 보고 산출 명시

## 6단계 — auditor

- 검증: 에이전트 정의의 tools가 정확히 Read/Grep인가 — 다른 도구 없음
- 검증: "의미적 대조로 판정, Grep은 탐색 보조" 문구 존재 — 부분문자열 판정 금지가 명시됐는가
- 검증: 3단계 판정(근거 없음/부분/있음) + 연결문 건너뛰기 + 통과 정의("근거 없음 0건, 연결문 제외") 존재
- 검증: "초안을 수정하지 않는다" 규칙 존재

## 7단계 — 마이그레이션 + 통합 검증 (실행형 테스트)

이 단계는 문서 점검이 아니라 **실행해서 통과를 확인**하는 통합 테스트다:

- 테스트: 마이그레이션 직전 커밋 확인 — `git log` 최신 커밋에 interview-state.md 변화 없음 확인 후 착수
- 테스트: pre-commit exclude 동작 — sessions/ 샘플 파일(행 끝 이중 공백 포함)로 `pre-commit run --files` 실행 시 해당 훅이 파일을 건드리지 않는다
- 테스트: 인용 손실 0 — 마이그레이션 후 인용 발언 카운트 = 16, 각 인용의 출처 표기가 세션 파일 경로를 가리킨다
- 테스트: 역분할 파일 무결성 — sessions/2026-08-15.md에 "세션 1 역분할" 각주 존재, frontmatter 스키마 준수
- 테스트: **dry-run 컴파일 파이프라인** — worker가 Stage 0 자료로 스켈레톤 초안 생성(빈 파일 아님), auditor 감사 보고서 산출, 근거 없음 판정 0건(연결문 제외), 산출물이 planning/dry-run/에 격리됨
- 테스트: 감사 오판 방지 샘플 — dry-run 초안에 표현만 바꾼 정당 서술 1개를 넣어 auditor가 "근거 있음/부분 근거"로 판정하는지 확인(부분문자열 오판 회귀 검사)
- 테스트: 스킬 로드성 — 새 SKILL.md 2종의 frontmatter가 파싱 가능하고(yaml 유효), references 파일 경로가 모두 실재하는가
- 테스트: (선택) plugin-dev:skill-reviewer 무경고 또는 경고 내용 기록

## 통과 기준 요약

각 단계는 위 스텁을 전부 통과해야 다음 단계로 넘어간다. 7단계 통합 테스트는 5절 검증 체크리스트(claude-plan.md)와 1:1로 대응한다 — 두 문서 간 불일치 발견 시 claude-plan.md가 우선이고 이 문서를 갱신한다.
