# Implementation Plan — career-memoir 스킬 패키지 개선 (rev 2)

작성: 2026-08-16. rev 2 = Opus 리뷰(iteration 1) 18건 반영(반영 내역: `claude-integration-notes.md`). 이 문서는 자기完結型(self-contained) 구현 청사진이다. 세션 대화·리서치 원문을 몰라도 이 문서만으로 구현할 수 있어야 한다. 배경 근거는 `planning/` 디렉터리의 spec·research·interview 참고.

## 0. 요약

경력 회고 에세이 프로젝트용 에이전트 스킬 패키지를 개선한다. 현재는 단일 `career-memoir-interviewer` 스킬(SKILL.md 87줄 + 경력 컨텍스트 1파일)로, 인터뷰 Stage 0(개괄)까지 완료된 상태다. 리서치 결과 오픈소스 대체재가 없어 로컬 스킬을 유지하되, 4개 개선 묶음(상태 구조 고도화, 질문 은행 보강, 세션 구조·게이트, 목소리·변환 분리)을 반영해 **스킬 2개 + 서브에이전트 3역할** 패키지로 확장한다. 산문 윤문(형태)은 기존 im-not-ai 플러그인(humanize-korean)이 담당하며 이 패키지가 갖지 않는다. **범위는 패키지 구축까지만** — 이후 에세이 집필 실행(Stage 1~N 인터뷰 등)은 별도 진행.

## 1. 배경과 근거 (왜 이 구조인가)

- **오픈소스 대체 불가 판정**: "경력 회고 특화 × 인터뷰 중심 × 장기 세션 연속성 × 감정 질문" 4축을 모두 만족하는 오픈소스가 없었다(공식 anthropics/skills 17개에도 없음). 특히 회고 윤리 원칙(패배 미화 금지, 개인 실수/구조 문제 구분)을 설계에 넣은 스킬은 발견되지 않았다.
- **오케스트레이션 기각**: Claude Code 스킬은 런타임 서비스가 아니라 컨텍스트에 로드되는 플레이북이라 호출 경계가 없고, 인터뷰 루프는 `AskUserQuestion`이 메인 컨텍스트 전용이라 서브에이전트로 위임 불가. 후보마다 상태 포맷이 달라 오케스트레이션 시 변환 계층이 순수 오버헤드. 오픈소스는 설계·콘텐츠 **차용**으로만 소비한다(MIT/Apache 확인분: pm-claude-skills, JobOps, enough, wayland).
- **서브에이전트 투입 기준**: 비대화형 + 입출력 파일 분리 + 컨텍스트 격리 이득. 세션 종료 정리·산문 변환·충실성 감사만 충족. 질문별 실시간 검증은 삽입 타이밍 실패 위험(연구에서 확인된 LLM 탐침의 최대 약점)으로 서브에이전트가 아닌 자기점검 체크리스트로 해결한다.

## 3. 구현 단계

단계 의존성: 1 → 2·3 (병행 가능) → 4 → 5 → 6 → 7. 1단계가 상태 스키마를 확정해야 나머지가 참조할 수 있으므로 가장 먼저.

### 1단계 — `references/state-schema.md` (상태 구조 고도화의 명세)

**목적**: 이중 상태 구조·holding 큐·세션 원문 형식을 확정한다. 이후 모든 산출물이 이 스키마를 참조한다.

**내용 요구사항**:

- **세션 원문 계층**(`sessions/YYYY-MM-DD.md`):
  - **파일명 규칙**: 세션 **시작일** 기준. 자정을 넘겨 이어진 세션은 한 파일로 유지(세션 로그에 시작·종료일 병기). 같은 날 세션을 다시 시작하면 `YYYY-MM-DD-2.md` 접미. `last_session`(frontmatter, 종료일)과 파일명(시작일) 불일치는 정상이다.
  - **형식**: 저자 발언 verbatim + 인터뷰어 질문 요지, 세션 시작/종료 시각, 다룬 시기·주제 태그.
  - **추기 빈도**: 저자 발언은 **답변을 받을 때마다**(늦어도 2~3답변 주기로) 파일에 append한다. 세션 종료에 몰아 쓰지 않는다 — 긴 세션에서 컨텍스트 압축이 발생해도 verbatim이 이미 디스크에 있어야 하기 때문이다.
  - **불변식**: 원문 계층이 **저자 발언의 source of truth**다. 한 번 기록된 내용은 수정하지 않는다(추가만 허용). "수정 금지"는 내용 기준이며 공백·포맷 정규화는 내용 변경으로 보지 않는다.
- **압축 상태 계층**(`interview-state.md`): 기존 7개 섹션(Spine, 시기별 진행, 인용 가능한 발언, 감정·패턴 노트, 미해결, 공개 경계, 세션 로그) + 신규 2개:
  - **holding 큐**(기존 "미해결"을 개명·확장): 각 항목에 유형(탐침 보관/미응답/실마리), 상태(보관 중/회수 완료/폐기), 회수 조건(어느 시기·세션에서 꺼낼지). 저자가 다루지 않은 주제는 "누르지 않고" 미응답 유형으로 기록한다.
  - **제안**(신규): distiller가 애매해서 직접 반영하지 못한 변경 제안을 쌓는 곳. 저자가 다음 세션 시작 시 승인/기각한다.
  - 인용 발언마다 출처 세션 파일 경로를 표기한다.
  - **압축 책임**(무한 성장 방지): 세션 로그는 최근 5개만 상세, 이전은 1줄 요약으로 롤오버. 인용 발언은 시기별 그룹화. 감정·패턴 노트는 중복 병합. 이 갱신은 distiller가 담당한다.
- **갱신 책임 분배**: 세션 중 인터뷰어는 원문에만 축적. 세션 종료 시 distiller가 원문을 읽어 압축 상태를 갱신. 인터뷰어의 압축 상태 직접 편집은 세션 로그 1줄 추가와 **Spine 긴급 갱신**(저자가 새 필수 사건을 명시적으로 확정하는 순간)만 허용.
- **Stage 완료 신호**: 컴파일러 게이트가 읽을 수 있는 형식으로 정의 — Stage 2 완료 = frontmatter `stage: 2` + 장면표 섹션이 존재하고 비어 있지 않음.
- **pre-commit 간섭 대응**: vault의 `.pre-commit-config.yaml`에 `초안/경력 회고 에세이/sessions/`를 prettier·whitespace 훅 exclude에 추가한다(원문 불변을 훅 차원에서 보장. `draft-vN.md`은 산문이라 포맷 무해하므로 제외하지 않는다). Obsidian Git 자동 커밋도 훅을 통과하므로 이 조치가 없으면 불변식이 어겨진다.
- **마이그레이션 절차**: 기존 `interview-state.md`의 Stage 0 산물(인용 16개, 패턴 노트) 손실 없이 이전. 세션 1(2026-08-15 시작·08-16 종료)은 원문 파일이 없으므로 기존 인용 발언을 `sessions/2026-08-15.md`로 역분할해 생성하고(각주에 "세션 1 역분할 — 채택 발언 목록, 원 대화 전문 아님" 명시), 인용 출처 표기를 "세션 1"에서 파일 경로로 바꾼다. frontmatter `stage/sessions/last_session` 유지. 스키마 문서에 **기존 섹션→신규 스키마 매핑 표**를 포함한다.

**완료 조건**: 두 계층의 파일 형식·추기 빈도·갱신 규칙·완료 신호·마이그레이션 절차·매핑 표를 모두 기술.

### 2단계 — `references/question-bank.md` (질문 은행 보강)

**목적**: Stage 1 시기별 심층 인터뷰에서 기본 8질문(상황/문제/행동/전환점/당시 해석/현재 해석/다음 시기에 남긴 것/관통 주제)을 보조하는 검증된 질문 은행.

**내용 요구사항**:
- **StoryCorps 파생 세트**: StoryCorps Great Questions(https://storycorps.org/participate/great-questions/) 중 경력 회고 적합 질문을 선별·한국어 번역. 최소한 Working/Remembering/Growing Up 계열에서 15개 내외. 각 질문에 원문 표기.
- **반사실·대가 보조 질문**: JobOps change-one-thing(https://github.com/reggiechan74/JobOps) 스타일 — "단 하나를 바꾼다면", "정말로 떠난 이유", "그 선택으로 얻은 것/잃은 것/희생한 것" 트레이드오프. 시기별 8질문의 4번(전환점)·7번(남긴 것) 옆에 배치.
- **씨앗 질문 미진행 3개 반영**: 아웃사이더 자각, 소수정예 추구, 사람을 성장시키는 일의 의미 — Stage 1 각 시기에 스며들 질문 변주 포함.
- **개인화 안내**: career-context.md의 회사·인물·연도 메타데이터로 일반 질문을 구체화하는 예시 2~3개(Storyworth Personalized Questions 방식).
- **라이선스 규칙**: 라이선스 미확인 저장소(memorist-agent, AutoSkill, writing-dna-discovery, bookstrap)에서 직접 복사 금지 — 발상만 자체 서술.

**완료 조건**: 모든 차용 질문에 출처 URL 표기, 8질문과의 연결 관계 명시.

### 3단계 — `references/probe-taxonomy.md` (탐침 분류)

**목적**: 후속 질문(탐침)의 유형 어휘를 제공해 인터뷰어가 "무엇을 위해 파고드는지" 선언하게 한다.

**내용 요구사항**:
- **탐침 3유형**: clarification(모호한 진술 해소) / elaboration(얇은 답변 확장) / contrast(대안 비교) + 감정 탐구형 추가(정성 인터뷰 방법론, https://www.koji.so/docs/probing-and-follow-up-questions).
- **표준 후속 3인자**: "그다음에 무슨 일이 있었나?" / "그때 어떤 기분이었나?" / "그 순간 무슨 생각을 했나?"(StoryCorps Tips 4의 한국어 역).
- **인용 앵커링 패턴**: 직전 발언의 구체적 명사·감정 단어를 인용해 파고드는 문형(예: "'싸움에서 벗어날 생각만 했다'고 하셨는데, 그 시점에 임직원들에 대한 최선은 무엇이라고 생각하셨나요?") — 4O4/memoir.bot 패턴.
- **구체성 강제(push back) 규칙**: 모호한 답변(예: "그때 좀 힘들었지")은 그냥 넘기지 않고 최소 1회 되묻는 규칙.
- **페이싱 안전 규칙**: 고통스러운 주제에서는 천천히·맴돌기·휴식 허용. 저자가 한마디 답변(후퇴 신호)을 내면 주제를 바꾸고 미응답으로 기록.

**완료 조건**: 각 유형에 한국어 예시 질문 1개 이상, 3유형+감정형 선택 시 선언 방식(질문 앞 각주 등) 정의.

### 4단계 — interviewer `SKILL.md` 재작성 + distiller 서브에이전트

**목적**: 코어 루프에 세션 구조·게이트·자기점검을 반영하고, distiller 호출 지점을 만든다. 이 단계에서 작성하는 에이전트는 **distiller뿐** — worker·auditor는 5·6단계에서 작성한다.

**SKILL.md 내용 요구사항** (기존 87줄 구조를 유지하며 다음을 반영):
- 기존 유지: 8질문, 5태도, 인터랙션 규칙(한 번에 한 질문, 패러프레이즈 선행, 감정 질문 스킵 금지, 추천 답 허용, 빈틈 탐지), progressive elaboration 단계(Stage 0~2).
- **세션 시작 루틴**(기존 "시작할 때마다" 확장): career-context 로드 → 압축 상태 복원 → **holding 큐에서 이번 세션이 회수 조건에 해당하는 항목 확인·꺼내기** → 제안 섹션 승인/기각 요청.
- **세션 3단 구조**: 워밍업(가벼운 확인 질문) → 본론(개방형) → 클로징 성찰 질문("이 시기가 전체 서사에서 어떤 자리인가"류).
- **세션 중 원문 축적**: 답변마다(늟어도 2~3답변 주기) 세션 원문 파일에 append(1단계 스키마 준수).
- **세션 종료 반사 단계**: 세션 끝에 그 세션 전체를 짧은 서사로 되짚어 저자가 확정(질문 간 패러프레이즈와 구분되는 별도 단계).
- **세션 종료 절차**: (a) 원문 파일 저장 확인 → (b) distiller 서브에이전트 호출(프롬프트에 원문·상태 파일 절대 경로 전달) → (c) 다음 세션 예정 질문 1개를 미리 공유(StoryCorps 팁 1).
- **질문 자기점검 체크리스트**: 질문 던지기 전 메인 컨텍스트에서 암묵적으로 1회 통과 — 4평가축(선의·필요성·맥락 인지·개방성) + 거부 가능성("저자가 거부해도 받아들일 질문인가") + 탐침 유형 선언. 체크리스트 자체는 SKILL.md에 6~8줄로 수록(매질문 적용이라 본문이 맞음).
- **완료 판정 기준**: 시기별 8질문 완료 판정에 "그 시기 경험을 동료에게 설명할 수 있는가" 외부화 기준 추가.
- **정리 게이트 명시**: 산문 작성은 컴파일러 스킬(`career-memoir-compiler`)의 몫이며 "정리 시작"을 사용자가 선언해야만 시작된다는 안내.
- **references 로드 규칙**: Stage 1 진입 시 question-bank.md·probe-taxonomy.md 로드, state-schema.md는 개요만 SKILL.md에 두고 상세는 필요 시 참조.
- **description(frontmatter) 갱신**: 트리거 라우팅은 description이 담당하므로, 인터뷰어 description에 부정 범위("산문 작성·정리·초안 생성은 career-memoir-compiler 담당")를 명시한다.

**`career-memoir-distiller.md` 에이전트 정의** (frontmatter name/description/tools=Read/Write/Edit):
- 입력: 세션 원문 경로 + 상태 파일 경로(호출 프롬프트로 전달).
- 임무: 원문에서 인용 가능한 발언 추출(출처 표기), 감정·패턴 노트 갱신, holding 큐 정리(회수 조건 충족 제안), 1단계의 압축 책임 수행(세션 로그 롤오버·인용 그룹화·패턴 병합), Spine 변경 제안.
- **사용자와 대화 불가** — 애매하면 "제안" 섹션에 남기고 저자가 다음 세션에서 승인.
- 산출: 갱신된 상태 파일 + 처리 요약.

**완료 조건**: SKILL.md이 신규 규칙을 모두 반영하고 3개 references를 올바르 참조하며 description에 부정 범위 포함. distiller 에이전트 frontmatter 유효.

### 5단계 — `career-memoir-compiler` 스킬 + 컴파일 worker

**목적**: "정리 시작" 선언 후 인터뷰 기록 → 충실한 산문 초안 변환. **"추출 not 생성" 원칙** — 초안의 모든 문장은 인터뷰 기록(세션 원문·인용 발언)에 근거해야 한다.

**스킬 SKILL.md 내용 요구사항**:
- **트리거**: "회고 초안 만들어", "정리 시작" 등. 인터뷰어 스킬과 분리된 트리거 공간.
- **description(frontmatter)**: 컴파일러 description에 부정 범위("인터뷰 진행은 career-memoir-interviewer 담당") 명시 — 라우팅 충돌 방지.
- **전제 게이트**: 사용자의 명시적 정리 선언 확인 + **Stage 2 완료 신호 확인**(1단계 스키마 정의: `stage: 2` + 비빈 장면표). 미완료면 무엇이 남았는지 보고하고 중단.
- **프로토콜 순서**:
  1. 상태 파일에서 Spine·장면표·공개 경계 로드.
  2. compiler-worker 서브에이전트에 지시: 세션 원문 전체를 먼저 읽고 목소리를 파악한 뒤(**목소리는 컴파일 시점에 원문에서 도출 — 별도 목록 상태를 두지 않는다. 스테일 방지. spec §4.4의 "목록 참조"에서 의도적으로 변경한 편차**) 장면 단위로 발화를 조립해 초안 작성. 각 장면 끝에 근거가 된 세션·인용을 각주 표기.
  3. auditor 서브에이전트로 충실성 감사(worker와 별개 호출 — 독립성).
  4. 근거 없는 문장이 있으면 worker가 교정(삭제 또는 인터뷰 기록 내 근거로 대체).
  5. **교정 후 재감사 1회** — 루프 상한 2회. 재감사에서 근거 없음 0건이면 통과, 상한 초과 시 사용자에게 보고하고 중단.
  6. 통과하면 초안 저장(경로: `초안/경력 회고 에세이/draft-vN.md`, 문서 말머리에 rev 주석). **버전 규칙**: N은 감사 통과 확정 시 증가, 교정 라운드는 같은 버전 내 수정.
  7. **im-not-ai 인계 안내**: 의미·구조 확정 후 `/ce-doc-review` → `/humanize-korean` 순서 권고를 사용자에게 표시(윤문은 직접 수행하지 않음).
- **비-목표 명시**: 윤문·문체 수정·사실 추가 창작 금지. 구조 변경 제안은 사용자 승인 후.

**`career-memoir-compiler-worker.md` 에이전트 정의** (tools=Read/Write):
- 입력: 상태 경로, 세션 원문 경로 목록, 장면표. 산출: draft 파일 + 조립 보고(장면별 사용 인용 수).
- 근거 없는 서술 금지, 각 장면에 근거 각주, 저자 발화 우선 인용.

**완료 조건**: 스킬이 게이트→지시→감사→교정→재감사→인계 순서와 루프 종료 조건을 기술하고, worker·auditor 호출 방식(Task 도구)이 명시됨. description에 부정 범위 포함.

### 6단계 — 감사 서브에이전트 (`career-memoir-auditor.md`)

**목적**: "검증 수단을 하나 더 확보" — 컴파일러와 다른 렌즈로 초안의 근거를 검증.

**내용 요구사항**:
- 도구 **Read/Grep만**(읽기 전용 강제). 초안을 수정하지 않는다.
- 입력: 초안 경로 + 세션 원문 경로 목록(+상태 파일 인용 섹션).
- **판정 방법**: 근거 판정은 **Read로 읽은 기록에 대한 의미적 대조**로 한다. Grep은 후보 위치 탐색 보조로만 사용 — 부분문자열 일치로 판정하지 않는다(표현을 바꾼 정당한 서술의 오판, 우연한 일치의 오통과를 막기 위함).
- 검증: 초안의 각 서술 단위(문장~짧은 단락)에 대해 근거 없음/부분 근거/근거 있음 3단계 판정. **연결문**(장면 사이 전환 서술)은 별도 표기하고 근거 판정에서 건너뛴다 — dry-run 같은 재료 부족 상황에서 무한 교정을 막는 안전 밸브.
- 산출: 감사 보고서(판정별 문장 목록 + 위치 + 이유).
- **통과 정의**: 근거 없음 판정 0건(연결문 제외).

**완료 조건**: 보고서 형식·판정 방법·통과 정의·도구 제한 명시.

### 7단계 — 상태 마이그레이션 실행 + 검증

**목적**: 기존 데이터를 새 스키마로 이전하고 패키지 전체를 시험.

**절차**:

2. `.pre-commit-config.yaml`에 sessions/ exclude 추가(1단계 정의).
3. `sessions/2026-08-15.md` 생성 — interview-state.md의 세션 1 인용 발언 16개를 원문 계층으로 역분할(각주에 "세션 1 역분할 — 채택 발언 목록" 명시).
4. `interview-state.md`를 새 스키마로 갱신(인용 출처 표기, 미해결→holding 큐, 제안 섹션 추가). 매핑 표(1단계)대로 손실 0 확인.
5. **dry-run 리허설**: Stage 0 자료만으로 컴파일 파이프라인 최소 동작 확인 — worker가 Spine 7항목+인용으로 아주 짧은 스켈레톤 초안을 만들고 auditor 감사. **통과 = 근거 없음 0건(연결문 제외)**. 산출물은 `planning/dry-run/`에 격리 보관(재현성 — 에세이 초안으로 쓰지 않음).
6. **파일 검증**: 5절 체크리스트 전수 점검.
7. (선택) `plugin-dev:skill-reviewer` 스킬로 품질 리뷰.

**완료 조건**: dry-run 통과 + 검증 체크리스트 전부 통과. 실패 시 해당 단계 파일 수정 후 재실행.
