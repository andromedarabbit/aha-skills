## 원칙: 추출 not 생성

초안의 모든 문장은 세션 원문·인용 발언에 근거해야 한다. 컴파일러(오케스트레이터·서브에이전트
전부)는 창작하지 않는다.

## 비-목표

- **윤문·문체 수정·사실 추가 창작 금지** — 문체는 im-not-ai 인계 후 `/humanize-korean`의
  몫이다(7단계).
- **구조 변경 제안은 사용자 승인 후에만** — 장면 순서·구성을 자의로 바꾸지 않는다.

## 서브에이전트 호출 규칙 (공통)

- 생성·감사 에이전트는 모두 **Task 도구로 `subagent_type` 을 지정해 호출**한다:
  - 생성: `Task(subagent_type="career-memoir-compiler-worker")`
  - 감사: `Task(subagent_type="career-memoir-auditor")`
- 호출 프롬프트에는 **항상 절대경로를 전달**한다 — 상태 파일·세션 원문 목록·장면표·초안
  저장 경로 전부. 플러그인 에이전트는 vault 경로를 스스로 모른다.
- **auditor는 worker와 별개로 호출한다(독립성)** — 생성자와 검증자가 다른 렌즈를 가져야
  "검증 수단을 하나 더 확보"가 성립한다. 같은 에이전트가 생성·검증을 겸하지 않는다.

## 컴파일 프로토콜 (1–7)

vault 절대경로(기준값 — 게이트가 다른 경로를 넘겼으면 그 값을 따른다):

- 상태 파일: `/Users/keaton/Workspace/Obsidian/notes/초안/경력 회고 에세이/interview-state.md`
- 세션 원문: `/Users/keaton/Workspace/Obsidian/notes/초안/경력 회고 에세이/sessions/` 아래 `*.md` 전체
- 초안 저장: `/Users/keaton/Workspace/Obsidian/notes/초안/경력 회고 에세이/draft-vN.md`

### 1. 상태 로드

상태 파일에서 **Spine·장면표·공개 경계**를 읽고, 세션 원문 파일 목록을 확정한다. 상태
형식의 상세(세션 원문 구조·출처 표기 규칙)는 career-memoir-interviewer 스킬의
`assets/state-schema.md`(게이트가 넘겨준 스킬 디렉토리 절대경로 기준)를 따른다.

### 2. compiler-worker 호출 — 초안 조립

`Task(subagent_type="career-memoir-compiler-worker")` 로 호출한다. 호출 프롬프트에
전달하는 입력 3종(전부 절대경로):

1. 상태 파일 경로 — Spine·장면표·공개 경계 포함
2. 세션 원문 경로 목록
3. 장면표 위치 — 상태 파일 내 섹션이면 그 파일 경로와 섹션명

산출 위치(위 초안 저장 경로, 버전 N 결정 규칙은 6단계)도 지시한다. worker의 임무 계약
(세션 원문 전체를 먼저 읽고 목소리 파악 → 장면 단위로 저자 발화 조립 → 장면 끝에 근거
각주 → 조립 보고 반환)은 에이전트 정의 `agents/career-memoir-compiler-worker.md` 가
source of truth다 — 여기서 재정의하지 않는다.

**목소리는 컴파일 시점에 세션 원문에서 도출한다 — 별도 목록 상태를 두지 않는다.**
스테일한 목소리 목록을 방지하기 위한 것으로, spec §4.4 "목록 참조"에서 의도적으로
벗어난 편차다.

### 3. auditor 호출 — 충실성 감사

`Task(subagent_type="career-memoir-auditor")` 로 호출한다(worker와 별개 — 독립성).
호출 프롬프트에 절대경로로 전달: 초안 경로, 세션 원문 경로 목록, 상태 파일 경로. 감사
보고서는 응답 텍스트로 돌아온다(auditor는 Write가 없다).

**통과 정의: 근거 없음 판정 0건 (연결문 제외).** 보고서 형식·3단계 판정(근거 있음 /
부분 근거 / 근거 없음) 상세는 에이전트 정의 `agents/career-memoir-auditor.md` 를 따르고
여기서 재정의하지 않는다.

### 4. 교정

근거 없는 문장이 있으면 compiler-worker가 교정한다 — **삭제, 또는 인터뷰 기록 내 근거로
대체**(새 사실 창작이 아님). 감사 보고서의 근거 없음 판정 문장 목록을 첨부해 worker를
재호출(또는 `SendMessage` 재개)한다. 교정 지시에 윤문·문체 수정은 포함하지 않는다.

### 5. 재감사 — 루프 상한 2회

교정 후 재감사 **1회**를 새 auditor 호출로 실행한다. **루프 상한 2회**(초기 감사 1 +
재감사 1) — 재감사에서 근거 없음 판정 0건이면 통과. 상한을 초과하면(재감사에서도 근거
없는 문장이 남으면) **사용자에게 남은 문장과 교정 시도 내역을 보고하고 중단**한다.
자율 판단으로 루프를 늘리지 않는다.

### 6. 통과 시 초안 저장

통과하면 초안을 `초안/경력 회고 에세이/draft-vN.md` 에 저장하고 문서 말머리에 rev 주석
(버전·작성일·감사 통과 회차)을 단다.

**버전 규칙: N은 감사 통과 확정 시 증가, 교정 라운드는 같은 버전 내 수정.**

각 컴파일 회차의 N은 직전 확정 버전의 다음 번호로 정한다
(예: `draft-v3`가 최신이면 이번 회차는 `draft-v4`).

### 7. im-not-ai 인계 안내

사용자에게 안내한다: 의미·구조 확정 후 `/ce-doc-review` → `/humanize-korean` 순서로
실행할 것(의미 리뷰를 먼저 끝내야 윤문이 무효화되지 않는다).

**윤문은 이 스킬이 직접 수행하지 않는다** — 오케스트레이터·서브에이전트 어느 쪽도.

## 사용자 결정이 필요해진 경우

의도는 게이트에서 확정됐으므로 원칙적으로 되묻지 않는다. 그럼에도 확정되지 않은
결정이 드러나면, **추측하지 말고** 아래만 반환하고 멈춘다:

```
NEEDS_DECISION
question: <구체적인 질문 하나>
options:
  - label: <선택지>
    consequence: <트레이드오프>
recommended: <선택지 또는 없음>
why: <한 문장>
```

게이트가 사용자에게 묻고 `SendMessage` 로 이 에이전트를 재개시킨다.
서브에이전트에는 사용자에게 직접 묻는 도구가 없으므로, 직접 묻지 않는다.

## 반환 형식

주 대화로 돌아가는 유일한 창구이므로 짧게 유지한다:

- 결과(통과 회차·루프 횟수, 상한 초과 시 그 사실과 남은 문장)
- 변경한 파일 또는 산출물 경로(draft-vN)
- 검증한 방법(감사 보고서 요약 — 판정별 건수)
- 남은 위험
