# blog-interviewer

블로그 글을 위한 저자 인터뷰를 진행하는 대화형 스킬. 한 번에 한 질문을 던지고 패러프레이즈로 확인하며, 저자의 발언을 세션 원문 파일에 verbatim으로 축적한다. 인터뷰어는 **산문을 쓰지 않는다** — 재료를 모으는 역할만 하고, 초안 작성은 `blog-compiler`가 담당한다.

## 무엇을 하나

- 저자(사용자)와의 인터뷰로 블로그 글 재료를 수집한다.
- 질문-답변을 Stage 0(주제·독자·논지) → Stage 1(재료 인터뷰) → Stage 2(형식·아웃라인) 순으로 진행한다.
- 세션 원문(`sessions/YYYY-MM-DD.md`)과 압축 상태(`interview-state.md`)의 이중 구조로 세션 간 진행을 유지한다.
- 세션 종료 시 `blog-distiller` 서브에이전트가 원문을 압축 상태로 증류한다.

## 언제 쓰나

- 블로그 글의 재료를 인터뷰로 새로 모으거나 이어서 모을 때.
- 산문 작성·초안 생성이 필요할 때는 이 스킬이 아니라 `blog-compiler`를 쓴다.
- 경력 회고 에세이 인터뷰는 `career-memoir-interviewer` 담당.

## 사용 예 (트리거 문구)

```text
블로그 글 인터뷰 시작하자
이 글 소재 인터뷰 이어서 해줘
my-blog-posts/ 인터뷰 이어서
```

세션 흐름 예:

1. "인터뷰 이어서" → 세션 시작 루틴(작업 루트 확정, 압축 상태 복원, holding 큐 회수, 제안 승인)
2. 워밍업 → 본론(개방형 질문 + 캘리브레이션 체크) → 클로징 성찰 질문
3. 세션 종료 → 반사 단계 → distiller 호출 → 다음 세션 예정 질문 1개 예고

## 상호작용 방식

`context: inline` 대화형 스킬이다. 저자와의 질문-답변 루프는 메인 컨텍스트에서 직접 돌고, 세션 종료 정리만 서브에이전트(distiller)로 위임한다.

## 데이터 위치 (경로 독립)

이 스킬은 특정 vault·저장소에 묶이지 않는다. 작업 루트는 호출 인자 또는 현재 디렉토리에서 정한다:

- 글 프로젝트 폴더: `<작업 루트>/<글-슬러그>/`
- 세션 원문: `<글 폴더>/sessions/YYYY-MM-DD.md`
- 압축 상태: `<글 폴더>/interview-state.md`
- 초안(blog-compiler 산출): `<글 폴더>/drafts/draft-vN.md`
