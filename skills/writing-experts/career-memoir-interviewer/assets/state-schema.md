## 0. 왜 상태가 두 계층인가

경력 회고 인터뷰는 여러 세션에 걸쳐 진행되며, 각 세션에서 저자의 발언을 verbatim으로 보존해야 컴파일 시점(산문 변환)에 근거 검증이 가능하다. 그런데 모든 세션의 원문 전체를 매번 컨텍스트에 로드하면 무한 성장한다. 그래서 상태를 둘로 나눈다.

| 계층 | 위치 | 역할 | 갱신 시점 |
| ---- | ---- | ---- | --------- |
| 세션 원문 | `sessions/YYYY-MM-DD.md` | 저자 발언의 source of truth. 세션 중 답변마다 append. 수정 금지(추가만 허용) | 인터뷰어, 세션 중 |
| 압축 상태 | `interview-state.md` | 인터뷰 진행에 필요한 요약(Spine, 진행 표, 인용, 패턴 노트) | distiller, 세션 종료 시 |

긴 세션에서 컨텍스트 압축이 발생해도 verbatim이 이미 디스크에 있어야 한다. 압축 상태는 원문이 보존되므로 언제든 재생성할 수 있다.

## 1. 세션 원문 계층 (`sessions/YYYY-MM-DD.md`)

### 파일명 규칙

- 파일명은 세션 **시작일** 기준 `YYYY-MM-DD.md`.
- 자정을 넘겨 이어진 세션은 한 파일로 유지한다. 세션 로그에는 시작·종료일을 병기한다.
- 같은 날 세션을 다시 시작하면 `YYYY-MM-DD-2.md`처럼 일련 접미를 붙인다.
- 압축 상태 frontmatter의 `last_session`(종료일)과 세션 파일명(시작일)이 다른 것은 **정상**이다. 세션 1이 정확히 이 사례다 — 파일명 `2026-08-15.md`, `last_session: 2026-08-16`.

### 파일 형식 (스켈레톤)

```markdown
---
session: N
started: YYYY-MM-DD HH:MM
ended: # 세션 종료 시 기입 (자정 통과 시 종료일이 시작일과 다를 수 있음)
periods: [] # 다룬 시기 태그 (저자의 실제 시기명 — vault 경력 맥락 파일 기준)
---

# 세션 N — YYYY-MM-DD

## 질문과 답변

### Q1 (인터뷰어 질문 요지)

> 저자 발언 verbatim
```

요건:

- (a) 저자 발언은 **verbatim** — 다듬거나 요약하지 않고 그대로 적는다.
- (b) 인터뷰어 질문은 **요지**만 기록한다(질문 원문 전체를 보존할 필요 없음).
- (c) 세션 시작/종료 시각을 frontmatter에 기입한다.
- (d) 다룬 시기·주제 태그를 `periods`에 남긴다.

### 추기 빈도

저자 발언은 **"답변을 받을 때마다"** (늦어도 2~3답변 주기로) 파일에 append한다. 세션 종료에 몰아 쓰지 않는다 — 긴 세션에서 컨텍스트 압축이 발생해도 verbatim이 이미 디스크에 있어야 하기 때문이다.

### 불변식

- 세션 원문 계층이 **저자 발언의 source of truth**다.
- 한 번 기록된 내용은 수정하지 않는다. 추가(append)만 허용한다.
- "수정 금지"는 내용 기준이다. 공백·포맷 정규화는 내용 변경으로 보지 않는다.

## 2. 압축 상태 계층 (`초안/경력 회고 에세이/interview-state.md`)

기존 7개 섹션(Spine / 시기별 진행 / 인용 가능한 발언 / 감정·패턴 노트 / 미해결 / 공개 경계 / 세션 로그)을 유지하고, 1개를 개명·확장하고 1개를 추가한다(전체 매핑은 §7 참조).

### Holding 큐 (기존 "미해결 / 다음 세션 포커스"를 개명·확장)

각 항목은 3개 필드를 갖는다.

- **유형**:
  - 탐침 보관 — 흐름 유지를 위해 미뤄진 후속 질문
  - 미응답 — 저자가 다루지 않은 주제. 누르지 않고 기록만 한다
  - 실마리 — 확인이 필요한 사실·URL 등
- **상태**: 보관 중 / 회수 완료 / 폐기
- **회수 조건**: 어느 시기·세션에서 꺼낼지. 인터뷰어의 세션 시작 루틴이 이 조건으로 회수 여부를 판정한다.

### 제안 (신규)

distiller가 애매해서 압축 상태에 직접 반영하지 못한 변경 제안을 쌓는 곳. 저자가 다음 세션 시작 시 승인/기각한다. distiller는 사용자와 대화할 수 없으므로 이 섹션이 유일한 이탈 밸브다.

### 스켈레톤

```markdown
## Holding 큐

| 내용 | 유형 | 상태 | 회수 조건 |
| ---- | ---- | ---- | --------- |

## 제안 (다음 세션 시작 시 승인/기각)

- (제안 내용 — 근거가 된 세션 파일 경로 표기)
```

### 추가 요건

- **인용 발언마다 출처를 세션 파일 경로로 표기**한다 (예: `sessions/2026-08-15.md`). "세션 1" 같은 별칭 표기는 폐지한다.
- **압축 책임** (무한 성장 방지 — distiller가 담당):
  - 세션 로그는 **최근 5개만 상세**, 이전은 1줄 요약으로 롤오버
  - 인용 발언은 시기별 그룹화
  - 감정·패턴 노트는 중복 병합

## 3. 갱신 책임 분배

| 주체 | 세션 원문 | 압축 상태 |

| distiller (세션 종료 시) | 읽기만 | 갱신 (인용 추출·패턴 노트·holding 큐·압축 책임·Spine 제안) |

## 4. Stage 완료 신호 (게이트 판정 가능 형태)

> **Stage 2 완료 = 압축 상태 frontmatter `stage: 2` + `## 장면표` 섹션이 존재하고 비어 있지 않음(장면표에 데이터 행 1개 이상).**

두 조건이 모두 충족될 때만 완료로 판정한다. 인터뷰어 SKILL.md와 compiler 양쪽에서 이 판정식을 **동일 문구로** 참조해야 한다 — 문구가 어느 한쪽에서 달라지면 게이트 판정이 갈린다.

## 5. pre-commit 간섭 대응 (명세만 — 실행은 마이그레이션 절차에서)

vault(`/Users/keaton/Workspace/Obsidian/notes`)의 pre-commit 훅(prettier, trailing-whitespace, end-of-file-fixer)이 원문 불변식을 어긴다. Obsidian Git 자동 커밋도 훅을 통과하므로 방치하면 세션 원문이 훅에 의해 재작성된다.

`/Users/keaton/Workspace/Obsidian/notes/.pre-commit-config.yaml`에서 `초안/경력 회고 에세이/sessions/`를 **2곳에** 추가한다:

1. 최상위 `exclude:` 정규식 — trailing-whitespace·end-of-file-fixer 적용
2. prettier 훅의 개별 `exclude:` 정규식 — prettier는 자체 exclude를 가지므로 별도로 명시해야 한다

`draft-vN.md`은 산문이라 포맷이 무해하므로 제외하지 않는다. 실제 yaml 수정과 `pre-commit run --files` 동작 확인은 마이그레이션 절차(§6) 실행 시점에 한다.
