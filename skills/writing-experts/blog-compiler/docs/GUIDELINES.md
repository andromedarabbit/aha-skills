# 구현 가이드 — blog-compiler

`career-memoir-compiler`(v1.0.0)의 골격을 복제해 블로그 글용으로 적응한 스킬이다. 일반화된 설계 원칙은 `docs/solutions/skill-design/career-memoir-interview-pipeline.md`(저장소 루트)를 따른다.

## 구조: 게이트 + 워커

- **SKILL.md는 게이트다.** 사용자의 명시적 "초안 작성" 선언과 Stage 2 완료 신호 2조건만 판정하고, 통과하면 오케스트레이션을 `WORKER.md`로 넘긴다.
- **WORKER.md는 `general-purpose` 서브에이전트가 Read로 실행한다.** 주 대화에 적재되지 않으므로 절차 전체를 여기 둔다 — `context: inline` 게이트(판정표 5행: 본문 길고 산출물 큼·입력은 조사 전 확정)의 비용 문제를 이 구조로 푼다.
- **게이트 판정식은 state-schema §4와 동일 문구로 양방향 고정** — 어느 한쪽이 달라지면 판정이 갈린다.

## 7단계 프로토콜 설계 근거

| 단계 | 근거 |
| ---- | ---- |
| 2 (worker 조립) | 세션 원문 전체를 먼저 읽고 목소리를 도출 — 별도 목소리 상태를 두면 스테일해진다 |
| 3 (auditor 독립 호출) | "검증 수단을 하나 더 확보" — 생성자와 검증자가 같은 표현을 쓰면 검증이 통과해버린다. auditor의 tools는 정확히 `Read, Grep` (읽기 전용 강제가 정체성) |
| 4-5 (교정·재감사, 상한 2회) | 무한 교정 루프 방지. 상한 초과 시 사용자 보고 후 중단 — 자율 판단 금지 |
| 6 (draft-vN) | N은 감사 통과 확정 시 증가, 교정 라운드는 같은 버전 내 수정 — 확정본과 작업본 구분 |
| 7 (윤문 인계) | 윤문은 의미 불변 전제이므로 의미 리뷰(`/ce-doc-review`)가 먼저. 컴파일러가 직접 윤문하지 않는다 |

## career-memoir 대비 차이 (적응 포인트)

- **경로 독립**: vault 절대경로 기준값을 없애고, 게이트가 글 프로젝트 폴더를 런타임에 확정해 워커·에이전트에 전달한다. 워커의 "기준값" 절이 사라지고 전달받은 절대경로만 쓴다.
- 초안 위치가 `<글 폴더>/drafts/draft-vN.md` 로 하위 디렉토리에 분리됐다(인터뷰 산출물과 구분).
- 장면표 → **아웃라인 표**(근거 컬럼 포함) — 조립·감사 단위가 장면에서 섹션으로 바뀌었다.
- 1단계에서 **공개 경계 위반 차단**을 명시했다(블로그는 외부 공개 글이라 경계 위반이 인터뷰 기록 근거 여부와 별개의 하드 실패 조건).

## 테스트

`scripts/tests/run.sh`은 플러그인 공용 러너(`skills/writing-experts/shared/test-runner.sh`)를 호출하는 래퍼다. 이 스킬의 래퍼가 켜는 검증:

1. 플러그인 `agents/` frontmatter 무결성 — blog-distiller/blog-compiler-worker/blog-auditor 3종 (필드·delimiter 쌍·name 값·tools 값).
2. 경로 독립성 회귀 — 스킬 문서 + 의존 에이전트 정의에서 홈 디렉토리 절대경로 패턴(`/Use`+`rs/`) 부재 확인.
3. **게이트 판정식 동일 문구 검사 — 이 스킬(소비자)이 판정식 5곳 전부를 검사한다** (자기 2곳 + blog-interviewer 3곳). "문구가 달라지면 게이트 판정이 갈린다" 불변식의 기계 검증.
4. bats·pytest·shell 통합 테스트가 있으면 실행.

## 컴파일 저장 규칙 (감사 전 잔류 방지)

조립·교정은 임시 경로 `drafts/wip-vN.md`에서 일어나고, 감사 통과 시에만 확정 경로 `drafts/draft-vN.md`로 저장된다. 루프 상한 초과로 중단하면 임시 파일을 삭제한다 — "N은 감사 통과 확정 시 증가" 규칙이 확정 경로의 의미를 보장한다.
