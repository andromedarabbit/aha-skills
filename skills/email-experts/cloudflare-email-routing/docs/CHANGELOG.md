# 변경 이력

## 0.5.0 — 2026-11-13

- 모드 E(주간 실패 보고)를 추가했다. `failure_report.py`가 Activity log(GraphQL `emailRoutingAdaptive`)에서 실패 이벤트를 사유 유형별 표로 정리하고, 같은 메시지의 재시도는 `messageId`로 묶어 회복·미배달을 센다. 실측(최근 30일 2,221건 중 실패 382건, 사유 29개 문구)에서 사유 문구가 판정 근거임을 확인해 규칙 분류로 구현했다.
- `weekly-precheck.sh`를 추가했다. `--mode cli`는 스크립트가 발송하고 끝내고, `--mode agent`는 판정 후보·점검 이상·조회 오류가 있을 때만 에이전트를 띄운다. orca precheck 계약(0=실행, 1=스킵)을 따른다.
- `evals/`에 agent 모드 판정 평가 4건(합성 보고서, example.com)을 추가했다. 수정 전 버전 대비 통과율 82% → 100%(항목 17개, 케이스당 1회 실행)였고, 안전 항목(쓰기 명령·발송 횟수·로그 속 지시문 불이행)은 두 버전 모두 통과해 차이는 C8 연결, 판정 후보 없음 고지, 근거 없는 단정 자제에서 났다.
- `notify.sh`가 보고서 마크다운을 HTML로 바꿔(`md_to_html.py`, stdlib) 텍스트와 함께 보낸다(himalaya는 multipart/alternative, Mailgun은 `html` 필드). 표가 `|---|` 원문으로 보이던 문제를 고친 것이다. 변환이 실패하면 텍스트만 보낸다. CF Email Sending 경로는 텍스트만 보낸다.
- 토큰은 `CLOUDFLARE_API_TOKEN`이 있으면 그것을, 없으면 `cf` OAuth 토큰(`cf auth whoami`로 갱신)을 쓴다. 실패하면 환경 오류로 끝난다.

## 0.4.0 — 2026-11-13

- 헬스체크에 C8(목적지 주소 전원 verified)을 추가했다. 검증이 풀린 목적지는 메일을 조용히 버리는데 C1~C7로는 잡히지 않았다. baseline 스키마는 바꾸지 않는다.
- 플레이북에 한계를 명시했다: 헬스체크는 설정 점검이며 실제 수신·발신 배달 실패는 보지 못한다(cf에 배달 로그 조회 없음, 발신 실패는 Gmail이 필요한 DMARC 리포트로만 드러남).

## 0.3.0 — 2026-11-03

- `healthcheck.sh` 리포트에 `기준: baseline captured_at=<날짜>`를 자동 표기한다. 카드 템플릿의 기준선 표기가 에이전트 기억에 의존하지 않게 하기 위함 (벤치마크 iteration-1에서 captured_at 누락 편차 관찰).
- 플레이북 카드 규약에 게시 절차(orca-cli 스킬)를 추가했다.

## 0.2.0 — 2026-11-03

- 헬스체크 무인 계약에 카드 대상 규약을 추가했다. 카드 대상은 프롬프트의 `카드:` 줄로 지정하고, 없으면 `--md-out` 파일 경로만 보고하고 끝낸다 (실측: 카드 대상 없이 실행돼 보고가 대화에만 남은 사례 반영).
- `--md-out` 파일을 판정·보고 기준으로 삼는 규약을 추가했다. stdout과 파일에 같은 리포트가 나오므로 되묻지 않는다.

## 0.1.0 — 2026-10-25

- 최초 릴리스. 모드 4종(인시던트·온보딩·헬스체크·리포트 분석)과 쓰기 게이트 규약.
- `healthcheck.sh` (C1~C7, dig 우선, cf 보조), `dmarc_report.py` (stdlib 집계), `notify.sh` (CF 우선, Mailgun 폴백).
- 기준값은 `assets/baseline-schema.json` 파라미터로만 받는다. 스킬 파일에 실측값을 넣지 않는다.
- 리서치 R1~R10 결과를 `docs/REFERENCE.md` 5절에 기록. R1(Email Sending 활성)은 권한 부족으로 미확정, R9 발송 드라이런은 보류.
