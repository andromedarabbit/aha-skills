# Git 저장소 폴더 전체 백업

현재 또는 지정한 Git 저장소 폴더를 사용자가 정한 로컬 경로 또는 마운트된 볼륨의 독립 restic 저장소로 수동 백업합니다. 기본적으로 `.git`, 숨김 파일, 미추적 파일과 민감정보도 포함합니다.

## 사용 방법

Git 저장소 안에서 `/backup-experts:git-restic-backup`을 호출하거나 “현재 Git 저장소 전체를 백업해줘”라고 요청하세요. 다른 저장소는 루트 경로를 지정하면 됩니다. 최초 설정, 백업 범위, 신규 저장소 초기화는 각각 확인합니다. 백업 성공은 복원 성공의 증거가 아닙니다.

## 백업 목적지

- **저장소 전체 경로:** “이번에는 로컬 `/backup/project-archive`에 백업해줘.” 경로를 그대로 사용합니다.
- **백업 루트:** “마운트된 볼륨의 `/mnt/backups` 아래에 원본 폴더명으로 백업해줘.” 원본이 `project`면 대상은 `/mnt/backups/project`입니다.

정해진 목적지는 없습니다. 이번 요청을 개인 설정보다 우선하고, 둘 다 목적지가 없으면 묻습니다. 마운트가 필요한 경로에서는 볼륨을 확인할 수 없으면 중단합니다. S3·SFTP 등 restic 원격 URL은 지원하지 않습니다.

Google Drive 데스크톱 앱 같은 macOS File Provider 폴더(`~/Library/CloudStorage/…`)도 선택할 수 있습니다. 제공자·계정·경로를 직접 확인하며, 확인할 수 없으면 중단합니다. 백업·검사·복원 성공은 이 기기에서 본 결과일 뿐 서버 업로드 완료를 뜻하지 않으니, 동기화 상태는 해당 앱에서 확인하세요.

## 요구사항과 문제 해결

`restic`과 1Password CLI `op`가 필요합니다. 외장 디스크나 NAS를 선택한 경우 올바른 볼륨이 마운트되어 있어야 합니다. 이 스킬은 restic CLI를 직접 사용하며 추가 플러그인을 요구하지 않습니다. CLI가 없으면 사용자가 준비한 뒤 스킬을 다시 호출하세요. 도구를 자동으로 설치하거나 인증을 변경하지 않습니다.

마운트·인증 실패, 빈 기존 저장소, 원본 불일치 또는 잠금이 생기면 중단합니다. 자동 초기화·잠금 해제·삭제는 하지 않습니다. 설정은 `~/.claude/skill-team-rules/git-restic-backup.md`에 비밀번호 없이 개인적으로 관리합니다.
