# Workspace restic 백업

## 개요

각 원본을 별도 restic 저장소에 백업한다. 스냅샷 생성은 원본의 애플리케이션 일관성이나 복원 가능성을 증명하지 않는다.

## 개인 설정과 우선순위

MR 스킬의 전역 개인 룰 방식처럼 `~/.claude/skill-team-rules/workspace-restic-backup.md`를 사용자가 직접 관리한다. 공용 스킬이나 Git 저장소에는 개인 경로, 계정, 비밀번호를 넣지 않는다. 우선순위는 **이번 요청 > 전역 개인 룰 > 기본값**이다. 안전 규칙과 승인 게이트는 어느 룰로도 해제할 수 없다. 파일이 없으면 최초 설정에서 원본 Workspace 루트, SMB 백업 루트, 1Password 항목과 비밀번호 필드 참조, 대상 저장소를 사용자에게 묻고 설정 전문을 보여 승인받은 뒤에만 해당 파일을 쓴다. 비밀번호 자체는 파일이나 대화에 쓰지 않는다. 이후 설정 변경도 변경 전후를 보여주고 별도 승인받는다. 요청에서 일회성으로 바꾼 값도 실행 전 승인한다. 파일이 모호하거나 비밀이 포함되면 중단하고 사용자에게 수정을 요청한다.

기본값: 명시된 Workspace의 선택한 저장소만, 원본별 독립 저장소 `<백업 루트>/<원본 폴더명>`, Workspace 공통 1Password 비밀번호, 제외 규칙 없음. Git 추적 여부와 관계없이 숨김 파일, `.git`, 자격증명·개인정보 등 전부 포함되므로 목록과 민감정보 포함 여부를 확인받고 필요한 제외는 구체적으로 승인받는다. 원본·대상·제외·비밀번호 참조를 임의 추론하지 않는다.

## 사용 방법

1. **의존성 확인.** `restic`, 1Password CLI `op` 및 호출 가능한 `restic:restic` 스킬이 있어야 한다. 범용 스킬이 등록되지 않았거나 호출 불가하면 중단하고 `restic@magnus-agent-skills` 설치를 별도 사용자 승인 후 직접 진행하도록 안내한다. 자동 설치, 인증 변경, 토큰 출력은 금지한다. 설치·호출은 미검증이므로 실패 시 추측하지 않는다.
2. **대상과 저장소 확인.** 원본 및 Workspace 루트를 절대 물리 경로로 해석하고 각 원본이 Workspace의 하위 디렉터리이며 실제 Git 작업 트리의 루트인지 확인한다. 원본이나 중간 경로의 symlink, 탈출, 원본 내부 중첩 대상, 백업 루트 또는 대상 경로의 symlink가 있거나 판정이 불가능하면 중단한다. 동명 원본은 기본 대상이 충돌하므로 중단한다. 원본과 모든 중첩 서브모듈 각각의 실제 Git 디렉터리와 Git 공통 디렉터리를 확인해 둘 다 백업 범위 안에 있어야 한다. 절대 경로 Git 포인터(`.git` 파일 또는 `commondir`)는 복원 위치가 바뀌면 깨지므로 중단한다. 원본과 각 서브모듈의 `objects/info/alternates`를 포함해 Git 객체 대체 경로를 재귀적으로 확인하고, 범위 밖 객체나 복원 후 깨지는 절대 경로가 있으면 중단한다. Git 경로를 바꾸는 환경변수는 제거한 상태에서 검사한다. 초기화되지 않은 서브모듈, 범위 밖 Git 디렉터리, 제외된 Git 데이터 또는 판정할 수 없는 경우에도 중단하고 별도 복구 가능한 백업을 안내한다. SMB 마운트 테이블에서 백업 루트가 실제 SMB 파일시스템에 속하고 예상한 서버·공유와 일치하는지 확인한다. 단순 디렉터리 존재만으로 마운트로 인정하지 않는다. 없거나 바뀌었으면 중단한다.
3. **범위·일관성 승인.** 실제 원본·대상 경로, 서버·공유, 포함·제외, 민감정보, 1Password 참조(값 제외), 예상되는 새 저장소 초기화와 스냅샷 생성을 보여주고 `AskUserQuestion`으로 승인 또는 취소를 묻는다. 실행 중 파일 변경 가능성을 설명한다. DB·VM 등 실행 중 데이터가 있으면 애플리케이션의 일관된 덤프/스냅샷 또는 정지 절차를 사용자가 마련해 확인할 때까지 해당 원본을 백업하지 않는다. 백업 도중 바뀐 파일이 경고되면 일관성 미보장으로 보고 재실행은 사용자 판단에 맡긴다.
4. **범용 스킬 확인.** 비밀번호 조회, 저장소 초기화나 백업에 앞서 Skill 도구로 `restic:restic`을 호출한다. 호출이 실패하면 중단한다. 호출 시에는 작업 계획만 요청하고 명령 실행 권한은 주지 않는다. 범용 스킬이 제안한 명령은 각 실행 전 이 문서의 승인과 안전 규칙으로 검토한다. 비밀번호는 외부 스킬에 전달하거나 출력하지 않는다.
5. **비밀번호와 기존 저장소 판정.** `op`로 참조를 조회하되 값을 출력, 명령 인자, 로그, 임시 평문 파일에 남기지 않는다. 조회·인증 실패나 빈 값은 즉시 중단하며 다른 비밀번호로 재시도하거나 새 저장소로 간주하지 않는다. 각 Bash 도구 호출은 별도 셸이므로 조회 성공과 비어 있지 않음을 같은 셸에서 확인한 다음에만 `RESTIC_PASSWORD`로 내보내 restic을 실행한다. 셸 추적은 끄고 명령 출력을 통해 비밀을 노출하지 않으며 종료 시 변수를 제거한다. 대상 경로가 없을 때만 신규 후보로 취급한다. 이미 존재하는 디렉터리(비어 있어도)는 초기화하거나 덮어쓰지 않는다. 기존 restic 저장소는 정상 인증 뒤 `restic snapshots --json`의 모든 스냅샷 원본 경로가 승인한 물리 원본 하나와 정확히 일치해야 한다. 스냅샷이 없거나 경로가 여러 개·다르거나 조회가 실패하면 중단한다. 인증 실패·잠금·손상은 신규 저장소의 증거가 아니다.
6. **실행 직전 재확인.** 승인한 원본, 경로, 제외, SMB 마운트 및 기존 저장소 판정을 다시 확인하고 달라지면 중단해 다시 승인받는다. 신규 대상은 여전히 존재하지 않는 경우에만 그 대상의 초기화에 대해 별도로 `AskUserQuestion` 승인 후 초기화한다. 레이스·예상치 못한 파일이 있으면 중단한다. 초기화 후 백업 실패 시 초기화된 빈 저장소가 남을 수 있으며 자동 삭제·재초기화하지 않는다.
7. **백업.** 환경변수·대상 경로가 확인된 경우에만 `restic backup`을 승인된 원본과 제외 규칙으로 수동 실행한다. 범용 스킬의 preflight는 마운트나 원본의 안전성을 증명하지 않는다.
8. **결과 확인.** 종료코드 0만 백업 성공이다. 종료코드 3은 일부 파일을 읽지 못한 부분 실패이며 스냅샷이 생겨도 성공이라고 보고하지 않는다. 다른 비영(非零) 코드, 잠금, 인증·네트워크 오류, 결과 불명도 실패 또는 불명으로 보고하고 자동 재시도하지 않는다. 대상별 스냅샷 ID, 실패 파일과 경고를 비밀을 가려 보고한다. 마지막에 비밀번호 환경을 정리한다.

## 검사와 금지 작업

백업 성공, `restic check` 저장소 검사, 별도 위치에서의 실제 복원 시험은 각각 다른 결과다. 검사는 잠금·캐시 쓰기가 가능하므로 별도 승인 후 정확한 저장소를 지정해 실행한다. `RESTIC_REPOSITORY_FILE`만 사용한 범용 스킬의 verify는 대상 지정 오류가 있을 수 있어 쓰지 않는다. 복원 시험은 대상·덮어쓰기 위험을 보여주고 별도 승인 후 빈 임시 위치에서만 한다. 하지 않았다면 하지 않았다고 보고한다.

`forget`, `prune`, `unlock`, 삭제는 이 절차의 승인에 포함되지 않으며 자동 실행하지 않는다. 사용자가 별도 승인해도 이 스킬 범위 밖으로 넘긴다. 예약, NAS 마운트·설정 변경, 인증 변경, 외부 스킬 설치, 커밋·푸시·MR도 하지 않는다.

## 예시

`/backup-experts:workspace-restic-backup` 또는 “선택한 Workspace 저장소를 다시 백업해줘”라고 요청한다. 경로와 범위를 확인하고 승인받은 뒤 실행한다.
