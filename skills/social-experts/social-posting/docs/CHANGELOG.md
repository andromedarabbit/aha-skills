# CHANGELOG — social-posting

## 0.13.1 (2026-11-19)

- Instagram 프로필 scan·bootstrap의 보조 페이지 종료 대기에 기존 수집 잔여 시간 제한을 적용한다. 종료 응답이 멈추거나 실패해도 이미 수집한 게시물과 원래 관찰 중단 사유를 반환한다.
- 실제 자식 전송 문자열과 부모 CLI를 실행하는 오프라인 회귀로 종료 정지·실패, 부분 사진·캡션·중단 사유 보존을 확인한다. 공개 Instagram 쓰기 차단은 유지하며 실제 ego 런타임의 종료 동작은 미검증이다.

## 0.13.0 (2026-11-18)

- 독립 instagram-expert와 선택 그룹 연결을 추가한다. 명시 선택한 사진 피드 조회·비교·보이스·캡션/사진 초안을 지원하며 기본 scan 네 플랫폼은 유지한다.
- 사진 1~20장·각 alt·빈 캡션 허용·공통 캡션의 단일 피드를 검사한다. 캡션 2,200 Unicode codepoint는 로컬 정책이며 공식 웹 계수 단위는 미확인이다. 사진 순서·권리·잘림 의도를 확인하고 자동 절삭·분할·영상 변환은 하지 않는다.
- 내부 게시 프로토콜·대상 read-back을 연결하되 publish와 공개 post는 `INSTAGRAM_UNVERIFIED`로 차단한다. Instagram을 승인 허용 목록에 넣지 않고 기존 혼합 작업·전체 계정 snapshot·게시 기록·scan 미디어 가드를 유지한다.
- 프로필 스크롤과 상세 조회 페이지를 분리하고 보조 페이지만 정리한다. 사진 전환·전체 미리보기 준비를 제한 시간 안에서 기다리며, 관찰 중단 전 캡션·사진과 원래 중단 사유를 scan·read-back에 보존한다.
- 오프라인 회귀와 신규 스킬의 독립 응답 비교는 실제 Instagram DOM·사진 첨부·게시 검증과 구분한다. 검증용 코드 변경과 일반 차단 해제·설치·Orca는 후속 별도 승인이다.

## 0.12.0 (2026-11-17)

- X·Facebook·Bluesky·Threads·LinkedIn 전문가를 독립 진입점으로 분리하고 social-posting은 선택 그룹의 조회·비교·초안·승인·게시를 조정한다. 조회를 게시 의도로 간주하지 않으며 기존 초안 게시에 재작성을 강제하지 않는다.
- 승인 질문에 표시한 대상만 digest로 기록하고 이전 승인 집합을 교체한다. 혼합 작업의 다른 초안·기록은 보존하며 publish의 하드 제약 검사도 선택 대상에 한정한다. 전체 계정 스냅샷과 기존 scan 사진·출처 동결 가드는 유지한다.
- 플랫폼별 UI 함수를 모듈로 나누되 기존 ego-post CLI와 자식 함수 직렬화·공통 수집 및 게시 루프를 유지한다. 플레이북 정본은 각 전문가가 소유하고 기존 경로는 호환 안내로 남긴다.
- 같은 카테고리의 공통 실행층을 공유하며 별도 wrapper·설정·플랫폼 그룹 스킬을 추가하지 않는다. Threads 쓰기 차단과 LinkedIn scan 비지원은 유지한다. 오프라인 회귀·응답 비교는 실환경 게시·설치 검증과 구분한다.

## 0.11.2 (2026-11-17)

- Bluesky에 `<time>`이 없는 실제 시각 링크 형태를 지원하고, 정상 UI가 받은 피드 응답의 `record.createdAt`을 같은 게시물 ID·작성자의 DOM 글에 결합한다. 분 단위 tooltip·상대시간·`indexedAt`·인용 글의 시각은 채택하지 않는다.
- 기존 응답 관찰의 잔여 시간 제한·종료 정리·지연 시각 보강을 재사용한다. 본문·사진·parent의 DOM 근거, 시각 미상·불완전 수집, 승인·게시·Threads 쓰기 차단 계약은 유지한다. 응답 평가와 실제 읽기 검증은 별도로 보고하며 이전 버전의 평가 성적을 재사용하지 않는다.

## 0.11.1 (2026-11-17)

- Facebook의 정상 UI 수신 Document·GraphQL 응답에서 동일 Story의 ID·permalink·작성자로 결합한 게시시각을 우선 보강한다. DOM 본문·사진·parent·신원 근거는 유지하고 다른 글·중첩 인용의 `creation_time`은 채택하지 않는다. 시각 미상과 불완전 수집도 유지한다.
- Bluesky 본인 프로필 오선택과 Threads 읽기 신원·게시물 추출을 보정한다. 오프라인 회귀와 실제 읽기 전용 검증은 별도로 판정하며, 실환경 성공이나 전체 이력 수집을 보장하지 않는다. Threads의 publish·직접 post 차단은 유지한다.
- Bluesky 사진은 같은 feedItem에 속하고 인용이 아닌 이미지만 수집한다. 같은 URL의 사진이 여러 개면 기본 선택을 거부하고 기존 `altOverride`의 digest·사진 ID로 구분한다. 로컬 파일 보관 CLI와 scan 출처 생성 경로의 문서 계약도 구분한다.
- Facebook의 선택적 응답 관찰과 종료 정리 대기가 수집 루프의 잔여 시간을 넘기지 않게 한다. 응답이 멈춰도 이미 수집한 글을 보존하며, 진행 중인 SDK 요청 취소나 이동·DOM 읽기의 전체 시간 제한을 보장하지는 않는다.
- 후속 답글을 직전 세그먼트의 게시 성공·확인된 URL에만 연결하고, URL 미회수·부분 게시·결과 불명 시 자동 이어쓰기를 금지하는 기존 실행 계약을 문서에 명시한다. 승인 훅·digest·사진 동결·Orca 책임 분리는 변경하지 않는다.
- 독립 응답 평가의 기존 5개 시나리오·채점 조건은 보존하고 이번 보정 직전 작업 트리와 최종 동결본의 비교를 별도 회차로 준비한다. 이전 평가를 최종본 성적으로 쓰지 않으며 미측정 시간·모델·토큰을 추정하지 않는다.

## 0.11.0 (2026-11-17)

- 게시 전 scan 사진·출처를 전용 임시 사본으로 복사하고 승인 digest를 대조한다. 실행 계층에는 사본 경로만 전달해 마지막 검사 뒤 원본 교체가 업로드에 반영되지 않게 한다. 성공·실패 모두 사본을 정리한다.
- 명시적인 X·Bluesky 부모 링크를 추출기부터 비교까지 전달한다. URL 없는 같은 노드의 반복 집계를 막고, X·Threads 첨부 사진에서 프로필·장식·중첩 인용을 제외한다. 같은 URL의 두 번째 사진도 관찰 ID로 선택해 alt를 보완할 수 있다.

- Threads의 전체 UTF-8 500바이트 오제한을 제거한다. codepoint 참고값과 미검증 경고를 내며 실제 게시 경로는 검증 전 차단한다.
- 같은 이미지의 서로 다른 원본 출처를 별도 provenance 파일로 보존한다. 이미지 signature와 출처 파일 digest를 검사하고 승인 후 변경은 거부한다. 기존 scan 사진 초안은 재준비·재승인이 필요하다.
- 최근 24시간 기본 구간·수집 한계·사진 선택·유사 후보 확인·최종 승인 절차를 연결하고 Orca 읽기 전용 전달 프롬프트를 추가한다. Orca 실제 등록과 실계정 검증은 포함하지 않는다.
- Facebook 게시시각·사진 전용 글과 Bluesky 사진 추출을 보완한다. 시간 미상은 별도 검토 목록으로 보존하고 관찰 중단 이유를 보고한다. 실행·플랫폼별 scan 디렉터리로 manifest 덮어쓰기를 막는다.
- 빈 본문끼리는 동일 글로 판정하지 않는다. 관찰된 parent 관계의 답글 묶음과 확인된 게시 기록을 비교 근거로 전달하며, 미발견을 미게시 확정으로 해석하지 않는다.
- 지정한 타인 게시물 URL을 단건 관찰하고 실제 게시자와 로그인 신원을 구분한다. manifest digest·사진 ID에 묶인 alt 보완을 지원하며 사진은 게시 작업의 `media/`에 보관한다. 다운로드는 HTTPS·리다이렉트 차단·same-origin 자격증명 정책을 요청하고 다른 origin의 최종 응답은 거부한다. SDK 옵션 적용·인증 다운로드·실제 업로드는 미검증이다.

- **플랫폼 DOM 셀렉터는 첫 실측 전 보수적 추정** — 첫 실환경 게시는 측정으로 취급해 기명 실패 코드로 셀렉터를 교정한다
