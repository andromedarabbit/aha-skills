# X 플레이북

canonical message를 X용 문안으로 바꾸는 규칙. 규칙은 세 등급으로 나뉜다 — 등급 정의와 근거는 `GUIDELINES.md` 참조.

## 규칙 표

### Hard constraint (위반 시 게시 차단 — check-drafts.py가 기계 판정)

| 규칙 | 값 | 비고 |
| --- | --- | --- |
| 가중 길이 | 게시물당 ≤ 280 | twitter-text v3 규칙: 라틴 등 일부 범위만 1, 한글·한자·이모지·비라틴은 2. URL은 23 고정 |
| 스레드 게시물 수 | 2~25개 | thread는 게시물 2개 이상, 상한 25(X 플랫폼 제한). 스레드는 x·bluesky만 지원 |
| 미디어 개수 | ≤ 4 | 이미지/GIF 기준 |

가중 규칙은 X 공식 카운팅 라이브러리 twitter-text v3(`config/v3.json`) 기준이다 — 화이트리스트 4개 범위만 1로 세고 나머지 전부(한글 음절·한자·이모지 ZWJ 시퀀스·비라틴 문자)는 2로 센다. 한글 140자가 상한이다. 플랫폼 정책 변경 시 `scripts/check-drafts.py`의 상수와 이 표를 함께 갱신한다.

### Platform convention (권고 — 위반이라고 알리지만 차단하지 않는다)

- **한 게시물에는 한 주장만** 담는다. 주장이 둘이면 스레드거나 잘못 쪼갠 것이다.
- **첫 줄 자체가 완결된 훅**이어야 한다 — 잘린 미리보기에서도 문장이 성립한다.
- 단일 포스트인지 스레드인지 **먼저 결정**하고 쓴다. 스레드로 결정했다면 게시물당 한 단계·한 장면만 담는다.
- **post_intent=teaser면 기본은 단일 포스트다.** 스레드는 소재 자체가 여러 독립 사실·단계를 나열할 때만 고른다 — 티저의 일은 클릭 한 번이지 논지 전달이 아니다.
- 스레드의 각 게시물 길이를 **일부러 다르게** 만든다 — 같은 길이가 반복되면 기계적 리듬이 드러난다.
- 글자 수와 이모지 사용은 최종 검사에서 다시 센다(check-drafts.py counts).

#### 스레드 구조 (`format: thread`)

스레드는 훅 → 바디 → 클로저 3존으로 짠다. 게시는 각 세그먼트가 이전 게시물에 대한 **답글로 연결된 체인**이 된다(publish.sh가 지시).

- **훅(첫 게시물)**: 1~2줄, 극단적으로 구체적이어야 한다. 읽으면 무엇을 얻는지 약속하고 호기심 루프("그중 3개는 보통 틀린다"류)를 연다. "A thread:" 라벨만으로는 훅이 못 된다. **첫 게시물에 외부 링크를 넣지 않는다** — 링크는 마지막 게시물로.
- **바디(2~N-1)**: 게시물당 아이디어·단계 하나. 각 게시물은 인용·링크로 중간에 유입된 독자에게도 자립해야 한다. 1~2줄마다 빈 줄로 숨 쉬게 한다. 최고 소재는 아껴두지 말고 앞(2번째 게시물까지)에 배치한다 — 탭 통과율은 깊이에 따라 감쇠한다. 다음 게시물을 암시하는 전환으로 끝낸다.
- **클로저(마지막)**: 스레드 전체를 한 문장으로 증류한, 가장 인용하기 좋은 문장으로 맺는다. CTA는 정확히 하나(저장·팔로우·답글 중 하나만) — 둘 이상 겹치지 않는다. "도움이 됐다면 RT"류의 반응 구걸은 금지.
- **번호 매기기**: "1/", "(1/N)" 관례. 번호는 게시 텍스트에 포함되므로 길이 제한 안에서 넣는다(제약 검사는 전문 기준이라 자동 반영).

### Performance heuristic (선택 힌트 — 게시를 차단하지 않는다)

| 힌트 | 근거 |
| --- | --- |
| 훅이 짧을수록 잘린 미리보기에서 살아남는다 (첫 줄 50자 내외 가이드) | X 미리보기 동작, 2026-08 관찰 — 플랫폼 UI 변경 가능 |
| 스레드는 마지막 게시물에 링크를 두는 게 클릭 유도에 유리하다는 관례 | 커뮤니티 관례, 정량 근거 없음 — 힌트로만 |
| 스레드 포맷 5종 — Listicle(나열형)·Story Arc(서사)·Framework(이름 붙인 프레임워크)·Breakdown(실제 사례 해부)·Contrarian(통념 반박). 재료 성격에 맞는 것을 먼저 고른다 | thread-writer-sms v1.3.0, 2026-09 채택 |
| 스레드 길이 3단계: 짧게 3~5개, 보통 7~10개, 길게 10개 이상(모든 게시물이 긴장을 올리는 스토리형만) | 커뮤니티 관례, 정량 근거 없음 — 힌트로만 |

## 공통 규칙 (모든 플랫폼)

- 숫자·고유명사·실제 경험이 없으면 **지어내지 않고 사용자에게 질문**한다.
- 검증 못한 기술 주장·성능 수치는 넣지 않는다.
- 복사가 아니라 플랫폼에 맞게 별도 작성한다 — canonical에서 다시 쓴다.
