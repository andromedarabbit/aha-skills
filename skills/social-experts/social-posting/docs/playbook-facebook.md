# Facebook 플레이북

canonical message를 Facebook용 문안으로 바꾸는 규칙. 등급 정의와 근거는 `GUIDELINES.md` 참조.

## 규칙 표

### Hard constraint (위반 시 게시 차단 — check-drafts.py가 기계 판정)

| 규칙 | 값 |
| --- | --- |
| 본문 길이 | 게시물당 ≤ 63206 codepoint |

미디어 개수 상한을 두지 않는다 — 근거가 불분명한 규칙을 하드로 만들면 정당한 게시를 막는다. 필요하면 근거를 확보한 뒤 `check-drafts.py`에 추가한다.

### Platform convention (권고 — 차단하지 않는다)

- **짧은 형(의견·질문·숫자)과 긴 형(스토리)을 먼저 구분**한다. 형이 구조를 정한다.
- **첫 줄만으로 핵심이 전달**돼야 한다 — 잘린 피드에서도 의도가 읽힌다.
- 청중(B2B/B2C/지역/커뮤니티)에 따라 어조를 바꾼다.
- **기업 자동문구를 금지**한다 — "We are thrilled to announce"류의 문장은 어떤 목소리에서도 어색하다.
- 링크만 던지지 말고 **그 링크가 왜 중요한지 설명**한다.
- **반응 구걸과 친구 태그 유도를 금지**한다 ("좋아요 눌러줘", "태그해서 보여줘").
- 대화체 — Facebook은 소셜 그래프 기반 대화 방이다.

### Performance heuristic (선택 힌트 — 게시를 차단하지 않는다)

| 힌트 | 근거 |
| --- | --- |
| "짧은 게시물(80자 이하)이 66% 더 좋다"류의 수치는 오래되고 출처가 불분명 — 힌트로만 | 낡은 통계 재인용 다수, 2026-08 조사 |

## 공통 규칙 (모든 플랫폼)

- 숫자·고유명사·실제 경험이 없으면 지어내지 않고 사용자에게 질문한다.
- 검증 못한 기술 주장·성능 수치는 넣지 않는다.
- 복사가 아니라 플랫폼에 맞게 별도 작성한다.
