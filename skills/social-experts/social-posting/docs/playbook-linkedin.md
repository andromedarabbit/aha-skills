# LinkedIn 플레이북

canonical message를 LinkedIn용 문안으로 바꾸는 규칙. 등급 정의와 근거는 `GUIDELINES.md` 참조.

## 규칙 표

### Hard constraint (위반 시 게시 차단 — check-drafts.py가 기계 판정)

| 규칙 | 값 |
| --- | --- |
| 본문 길이 | 게시물당 ≤ 3000 codepoint |
| 미디어 개수 | ≤ 9 |

### Platform convention (권고 — 차단하지 않는다)

- **주제와 훅을 독립적으로 선택**한다. 좋은 주제가 곧 좋은 첫 줄은 아니다.
- **원하는 반응에 따라 구조를 바꾼다** — 댓글을 받으려면 질문·여지로 끝내고, 공유를 받으려면 쓸만한 요약을, 저장을 받으려면 체크리스트 형태로.
- **첫 화면(above-the-fold)을 별도로 최적화**한다 — "더 보기"가 펼쳐지기 전 3~4줄이 관문이다.
- 실제 취약성·구체적 이해관계·숫자·고유명사를 **요구**한다. 추상적 교훈만으로는 승격하지 않는다.
- 모바일 가독성: 문단을 짧게, 한 문단 한 생각.

### Performance heuristic (선택 힌트 — 게시를 차단하지 않는다)

| 힌트 | 근거 |
| --- | --- |
| "본문 밖 링크가 도달률을 40~60% 줄인다"류의 수치는 오래되거나 출처가 불분명 — 링크는 댓글로 미루라는 **힌트로만** 쓰고 차단 근거로 쓰지 않는다 | 낡은 통계 재인용 다수, 2026-08 조사 |
| 근무 시간 초반 게시가 노출에 유리하다는 관례 | 정량 근거 불명확 — 힌트로만 |

## 공통 규칙 (모든 플랫폼)

- 숫자·고유명사·실제 경험이 없으면 지어내지 않고 사용자에게 질문한다.
- 검증 못한 기술 주장·성능 수치는 넣지 않는다.
- 복사가 아니라 플랫폼에 맞게 별도 작성한다.
